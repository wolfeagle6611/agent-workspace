# ADR 0001: 权威状态放在 Durable Object 的 SQLite

Status: accepted（外部系统既成决策，本文为逆向整理）

## 背景与决策

容器会重启、会被回收、会被换掉。所以不能让它持有真数据。Cloudflare Computer 把 Workspace 的全部状态放进 Durable Object 的 `ctx.storage`，容器只拿一份可丢弃的镜像。容器没了，下一次 push 从 DO 重建。

这条决策决定了后面所有设计：同步协议存在、水位线存在、容器被当作可淘汰资源、`computerd` 用进程生命周期的临时库。

## 放弃的方案

**容器为权威。** 直接挂容器磁盘，DO 只做转发。放弃原因：容器寿命短于会话，重启即丢数据；且 DO 侧就无法在没有容器时读文件。

**双主写入。** 两边都可写且都算数。放弃原因：需要真正的冲突解决机制，成本远超收益。现在明确是 last-write-wins。

## 后果

- DO 存储上限决定 Workspace 上限，约 10 GB，与 DO 共享配额。
- 所有容器内写入都要回流。`npm install` 这类大量小文件操作的真实成本在 pull，不在挂载（见 docs/19 与 issue #179）。
- 容器侧可以整份丢。代价是重启后要重新基线化。

## 对本项目的影响

Go 版必须回答同一个问题：谁是权威。若权威放在进程内内存或本地磁盘，就不需要同步协议，但也得不到跨重启与跨实例的可寻址性。
